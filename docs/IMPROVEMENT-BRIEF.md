# DLSSGManager 功能与 UI 改进任务书

编制日期：2026-10-24。目标平台：Windows 10/11、WPF、.NET 8。

## 1. 产品目标与范围

面向给游戏配置帧生成的普通用户，以及管理多个游戏的熟练用户。主流程围绕“找到游戏 → 看懂状态 → 调整配置 → 确认变更 → 应用并查看结果”展开，恢复入口始终可找到。

本轮重点是功能增量与界面体验。版本整理和发行文档仅作为实施后的必要收尾。

已有的扫描、搜索筛选、多源下载、离线导入、暂停续传、自动接管、批量操作、主题和语言切换继续复用。以下标注“新增”的条目是建议实施内容，不表示已经实现。

### 当前依据

- `GameManagementViewModel.Refresh` 已区分未保存、待应用和已应用，但界面没有逐项配置差异。
- `RunDeploy` 完成反作弊确认后直接调用部署服务，尚无面向用户的变更摘要。
- `MainWindow.xaml` 中批量结果由只读 TextBox 显示，主要操作随详情一起滚动。
- `GameProfile` 已具备 `Clone/CopyFrom`，可承接参数复用；未发现用户配置方案的管理入口。
- 现有参数区已有部分 DLSS/XeSS 启用条件，继续补齐说明与一致性，不重新实现引擎适配。

以上依据来自源码；视觉问题需在实施时用当前程序截图确认。工作区已有未提交调整，实施时承接这些改动。

## 2. 功能改进

### F1 · P0：配置差异与应用摘要〔新增〕

**解决的问题：** 用户能看到“待应用”，但不知道具体改了哪些项，也无法在应用前快速确认目标。

- 增加“查看变更”，逐项显示参数名称、上次应用记录值、当前待应用值。
- 分别表达“尚未保存”和“已保存但未应用”；名称、启动路径等管理信息与写入游戏的配置分开显示。
- 应用摘要呈现目标游戏、渲染目录、代理入口、当前负载与待应用配置；放在详情中按需展开，避免每次操作新增普通确认弹窗。
- 应用后显示实际结果和“需重启游戏”的提示，提供启动游戏、查看详情入口。
- 旧记录没有快照时明确写“无上次配置记录”，不推断旧值。快照用于比较配置，不代表游戏当前文件已逐项核验。

**验收：** 修改倍率与优化档位后，只显示这两项的已知参数差异；仅保存后仍显示待应用；成功应用后按新记录刷新。应用失败时不提前清空差异，不显示成功。

### F2 · P1：保存方案、复制参数与恢复默认〔新增〕

**解决的问题：** 相似配置需要在不同游戏中重复手工设置，调参后缺少便捷的复用入口。

- 增加“我的配置方案”：将当前参数命名保存、选用、重命名和删除；方案与上游的 A/B/C“渲染预设”使用不同名称。
- 增加“从其他游戏复制参数”，先显示将变更的字段，再填入当前编辑区。
- 复用范围限于帧生成与相关可配置参数；游戏路径、代理入口、部署记录、备份和反作弊确认不随方案复制。
- 增加“恢复项目默认参数”，使用当前能力支持的默认值，并保留应用前的差异提示。
- 载入方案和恢复默认只修改当前编辑配置；保存、应用仍由用户主动执行。不提供未经实测的性能或画质承诺。

**验收：** 从游戏 A 复制参数到 B 后，B 的路径、代理入口、部署记录和备份保持原值。修改方案名称不改变游戏参数，删除方案不影响已使用该方案的游戏。

### F3 · P0：参数联动与就地解释〔完善〕

**解决的问题：** 部分控件能禁用，但用户还需要知道原因、实际生效值和解决方式。

- 根据引擎、当前负载能力及 INI schema 展示相关参数，沿用现有支持范围。
- DLSS/XeSS 切换后，就地说明倍率、优化档位、渲染预设等参数的适用条件；不生效的已保存值明确标记。
- 超分所需文件不足时，在开关旁说明缺失原因，并提供获取完整包的入口。
- 对不支持的组合给出具体字段和修正入口，应用按钮与快捷键使用同一套可执行条件。
- 切换引擎或载入方案时保留用户参数；确实需要调整取值时，展示原因和变更，不静默覆盖。

**验收：** 用户能在对应控件旁知道“为什么不能选、怎样可以用”。切换引擎再切回时已有参数可恢复；不支持的配置无法绕过按钮状态直接应用。

### F4 · P1：结构化批量结果与停止剩余任务〔新增与完善〕

**解决的问题：** 整段文字结果不便定位失败对象，也不便判断下一步。

- 将批量结果改为逐行列表：游戏、操作、结果、简要原因、详情入口。
- 支持查看全部/失败项，点击结果定位对应游戏；隐藏于当前筛选的游戏需先说明筛选影响。
- 保留“只重试失败项”，执行前显示本次重试对象；普通批量操作继续只处理当前可见且勾选的对象。
- 提供“停止剩余任务”：当前单游戏文件操作完成收尾后停止，不在文件替换中途强制中断；尚未开始的项目标记为未执行。
- 成功、失败、跳过和未执行分别计数，区分“从未执行”和“执行后失败”。

**验收：** 多游戏出现部分失败时，可直接定位失败游戏并重试；成功项不重复处理。停止后能看清已完成与未执行对象，现有备份与恢复规则继续生效。

### F5 · P1：游戏库查找与列表信息〔新增与完善〕

**解决的问题：** 游戏增多或名称相同时，需要更快找到正确目标。

- 在现有名称搜索基础上支持路径关键字；保留状态筛选，并提供明确的清除入口。
- 新增名称排序与“需处理优先”排序，排序结果稳定，切换语言不改变游戏标识。
- 列表项显示游戏名、简短路径及主要状态，长路径可查看或复制完整内容。
- 明确区分“当前打开的游戏”与“用于批量处理的勾选”，点击勾选框不意外切换正在编辑的游戏。
- 筛选和排序保留选中游戏的配置；当前对象被筛出时明确提示其可见性，不把编辑内容错误显示到其他对象。

**验收：** 同名游戏可通过路径区分；名称与路径搜索均可命中。调整排序、筛选或批量勾选后，当前编辑对象和待保存配置保持对应。

### F6 · P1：下载结束后的应用引导〔完善〕

**解决的问题：** 下载本地 Mod 和更新游戏是两个步骤，需要把衔接讲清楚。

- 下载窗口分别展示完整包/基础包提供的能力、当前来源、下载阶段及可用操作。
- 本地负载、游戏已部署版本和管理器版本分别命名，避免把运行库构建号直接当作管理器版本。
- 下载或离线导入成功后显示本地负载摘要，并提供“查看需更新游戏”入口。
- 复用现有“勾选可更新”，展示待处理范围，再由用户主动应用。
- 失败和取消后保留已有负载；结果区解释后续可重试、换源或离线导入的实际可用操作。

**验收：** 下载成功不会自动修改游戏。用户能从完成提示找到待更新对象；同版本重新下载不把所有游戏误标为必须升级。

## 3. UI 改进

### U1 · P0：主窗口布局与操作层级

保留桌面工具的双栏结构，形成稳定的游戏库、当前游戏、配置和操作区域。建议布局：

```text
┌─────────────────────────────────────────────────────────┐
│ 图标 / 应用名           本地 Mod 状态  下载/更新  设置   │
├───────────────────┬─────────────────────────────────────┤
│ 游戏库 / 添加     │ 当前游戏名称 / 部署与配置状态       │
│ 搜索 / 筛选/排序  │ 版本摘要 / 查看变更 / 最近操作结果   │
│                   ├─────────────────────────────────────┤
│ 游戏名、短路径    │ 常用配置                            │
│ 状态与批量勾选    │ 高级配置 / 参数说明                  │
│                   │ 详情可滚动                          │
│ 批量选择与操作    ├─────────────────────────────────────┤
│                   │ 保存配置   应用到游戏   更多操作    │
├───────────────────┴─────────────────────────────────────┤
│ 当前任务 / 最新结果                         展开日志    │
└─────────────────────────────────────────────────────────┘
```

- 详情滚动时，当前游戏标识与保存/应用操作保持可见。
- 主要动作使用一个强调按钮；保存保持次级层级。恢复作为明确的危险操作，在固定“更多操作”中可达。
- 删除日志选项随恢复操作展示，避免与日常保存/应用并列造成误解。
- 游戏名称、配置状态、部署版本与最近操作结果分别表达，不堆成同一段文字。
- 批量结果独立展开，不占据单游戏配置的首要位置；系统主题与语言入口收敛到设置区。

**验收：** 用户在编辑区底部仍能确认当前游戏并保存/应用；普通配置操作不必跨多个折叠区寻找按钮，恢复入口路径固定。

### U2 · P0：配置分组、信息密度与文案

- 常用区优先呈现帧生成开关、引擎、倍率和优化档位；XeSS 专属项按条件出现。
- 高级区容纳代理入口、渲染预设、超分、GPU 计时与日志；关键依赖说明靠近字段。
- 每项参数采用“名称、控件、必要时一行解释”的结构；展开更多说明时不挤压主要操作。
- 统一使用“保存配置”“应用到游戏”“更新本地 Mod”“恢复游戏文件”等明确动作名称。
- 空库提供扫描/添加入口；搜索无结果提供清除筛选；未选择游戏说明下一步。

**验收：** 首次使用者能说明保存与应用的区别，能找到引擎、倍率及依赖条件；状态或警告变化后，文案和可执行动作一致。

### U3 · P1：视觉规范、主题与桌面适配

- 沿用现有深浅主题和绿色强调色，以中性背景、清晰分隔和字重建立层级。
- 使用 Segoe UI / Microsoft YaHei UI；正文以 13–14 DIP 为起点，主要说明不依赖小号灰字。
- 统一按钮、输入框、列表行、间距和焦点样式；主要按钮高度约 32–36 DIP，实际尺寸以缩放后的可用性为准。
- 列表宽度可调整；长名称、路径及英文说明采用合理换行、省略和完整内容入口。
- 窗口缩小时重排工具栏，配置区域可滚动；下拉框和弹窗跟随当前主题。
- 动效仅用于展开、进度及状态反馈，短且不阻碍连续操作。

**验收：** 在 1366×768、100% 和 1920×1080、125%/150% 下，关键按钮可达；中英文、深浅主题下无文字覆盖、无法辨认的选中项或丢失的键盘焦点。

### U4 · P1：图标与控件状态

- 应用图标沿用“深灰圆角底 + 绿色交错画帧形成 D”的方向，交付 SVG、PNG 与多尺寸 ICO，并接入 EXE 和窗口。
- 界面动作图标采用统一笔画与尺寸；关键动作保留文字标签。
- 控件具备可辨别的默认、悬停、按下、焦点、禁用与忙碌状态。
- 成功、警告、失败同时用文字和视觉标识表达；错误靠近相关字段或操作结果，日志提供细节。

**验收：** 桌面、标题栏与任务栏图标一致，小尺寸可识别；无鼠标时可完成主要路径，不靠颜色猜测结果。

## 4. 实施顺序与交付

**第一批：** F1、F3、U1、U2。先完成配置可理解、主操作可达和应用结果明确的闭环。

**第二批：** F2、F4、F5、F6、U3、U4。补齐多游戏效率、下载衔接和视觉细节。

每批交付可运行绿色版、对应界面截图、实际变更列表和人工验收结果。功能尚未实现、未核验或受外部条件阻碍时分别说明，不能用界面占位代替功能完成。

实现保留现有技术栈、文件归属校验、备份结转、反作弊确认与下载校验。配置方案和预览不获得写入游戏目录的额外权限；文件写入仍由用户主动应用或恢复触发。真实游戏目录写入需有对应操作授权。

沿用此前要求：不恢复已删除的测试项目，不增加测试或冒烟门禁；进行必要构建与针对本次改动的人工验收。版本、README 与发行说明随实际实现同步收尾。本任务书不触发代码实施或新版本发布。
