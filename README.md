为 [dlssg_for_sm86](https://github.com/sdli1995/dlssg_for_sm86) 提供图形化管理界面：支持扫描查找游戏、按游戏独立配置帧生成参数、部署代理 DLL、一键恢复原文件，并管理本地 Mod 更新。

主要面向 **RTX 30 系显卡**（维护者在 RTX 3080 Ti 上进行实测）。管理器负责配置与文件操作，帧生成的画质、性能和游戏兼容性取决于上游 Mod、驱动及游戏本身。

## 核心特性

- **免安装即开即用**：提供单文件绿色版，下载后放入可写目录直接运行。
- **多源下载与离线导入**：支持多下载源自动测速、暂停、继续与跳过当前源，也支持直接拖入上游 ZIP 压缩包离线导入本地负载。
- **按游戏独立配置**：支持按游戏保存帧生成倍率、优化档位及高级设置（代理入口、预设、日志级别、逐帧 GPU 计时）。
- **自动接管与安全恢复**：检查状态时自动接管已识别的手工安装，包括已收录的社区版代理；恢复时按文件哈希与固定指纹的项目签名严格校验归属，还原原配置备份并保留未知文件。中途断电或强退，下次启动自动收尾。
- **逐文件校验的 Mod 下载**：无论来自哪个下载源，每个文件都必须与发布版清单的哈希完全一致才会被采用；各版本分目录存放，可回退。
- **按需提权**：游戏目录需要管理员权限时只为这一次操作提权，管理器本身不以管理员身份运行。
- **批量管理与平滑升级**：支持结合搜索与状态筛选进行批量部署、批量恢复及失败项重试，从 0.3.x 升级至 0.4.0 时自动清理多余的旧版代理。
- **反作弊风险提示**：自动检测带内核级反作弊的游戏并弹出警告，需手动明确确认后才执行部署。

## 下载与运行

后续仅提供**免安装绿色版**，请前往 **[最新发行版](https://github.com/BUNNY-19C/DLSSG-30s-manager/releases/latest)** 下载：

| 文件 | 适合的用法 |
|---|---|
| `DLSSGManager.exe` | 绿色版，单文件，放到任意可写目录双击运行 |
| `dlssgm.exe` | 可选的命令行版，与界面版共用游戏库，适合脚本与批量操作（`dlssgm --help`） |
| `SHA256SUMS.txt` | 用于核对程序文件的 SHA256 |

- **运行要求**：支持 Windows 10 / 11 x64，**无需安装，也无需另外安装 .NET**，将程序放入可写目录即可双击运行。
- **Mod 文件获取**：Mod 文件单独下载，首次启动时会自动获取，也可以点击「下载 / 更新 Mod 文件」手动获取。
- **附加文档**：[v1.13.0 更新说明](docs/RELEASE-NOTES.md) · [Mod 文件与授权说明](docs/mod-files.md)

## 第一次使用

1. **准备环境**：**关闭要修改的游戏**，启动管理器，等待 Mod 文件下载完成。
2. **添加游戏**：点击「扫描 Steam 库」「扫描文件夹…」或「添加游戏…」，选择游戏。确认渲染目录是实际运行游戏的 EXE 所在位置，避免选成启动器目录。
3. **调整参数**：在详情中调整帧生成倍率和优化档位；代理入口、预设、日志级别放在「高级设置」中。
4. **部署生效**：点击「部署到该游戏」，已有部署则点击「应用到游戏」。完成后启动游戏，并在游戏内开启相应的帧生成选项。
5. **卸载恢复**：想撤销时关闭游戏，点击「一键恢复」。

顶部状态卡显示当前游戏状态、配置状态、本地负载和游戏已部署版本。名称搜索和状态筛选可组合使用；工具区和运行日志可以展开，日志收起时仍显示最新结果摘要。

> [!WARNING]
> **带内核级反作弊的游戏存在账号风险。** 反作弊可能拦截、隔离代理 DLL 或记录检测结果。管理器会检测并提示，部署需要你明确确认；确认提示不代表游戏允许使用此类 Mod。

## 配置、构建与更新

### 保存配置与应用到游戏

配置按游戏独立保存。保存失败会持续显示错误和「重试保存」入口，请先完成保存再退出。

| 操作或状态 | 含义 |
|---|---|
| **保存配置** | 保存到管理器的游戏库，不写入游戏目录 |
| **部署 / 应用到游戏** | 将一个代理 DLL、配置与 `dlssg_sm86/` 运行目录写入游戏渲染目录 |
| **未保存** | 当前配置与管理器已保存的配置不同 |
| **已保存、待应用** | 管理器已保存配置，游戏尚未应用；旧记录缺少配置快照时也会显示此状态 |
| **已应用** | 当前配置与上次部署记录一致，修改后需重新应用并重启游戏 |

### 上游 0.4.1

**驱动要求：NVIDIA R580 或更新版本。** 旧驱动不再回退 PTX；不支持的旧游戏帧生成插件可能被上游拒绝，请查看游戏日志中的原因。

| 构建 | 倍率 | 优化档位 | DLSS 预设 |
|---|---|---|---|
| `310.9.16`（当前） | DLSS 2X–6X；XeSS 2X / 3X / 4X | DLSS：0–3，新配置默认 1 | A / B / C |

- **下载与默认项**：下载固定适配 **0.4.1 Release 完整包**，包含超分文件；基础包仅提供插帧与 XeSS。新游戏默认 DLSS、档位 1、预设 A、超分关闭，已有游戏的档位和 DLSS 倍率保留。XeSS 倍率单独保存，已有配置保持 2X，可手动选 3X / 4X。
- **倍率与预设**：0.4.1 将倍率视为必须支持的请求；游戏菜单可选更低，无法满足请求时拒绝启用，而非自动降档。A / B / C 不受游戏或驱动覆盖；已有 Auto 设置保留显示，但在 0.4.1 写成 A。C 是轻量插帧，HUD 和遮挡边缘画质略低。
- **XeSS**：支持 `CoarseAt4K`（输出像素数达到 3840×2160 时用 Coarse，否则 Middle），无 HUD 输入可选 Auto / 严格启用 / 关闭。旧“优先无 HUD”迁移为 Auto；不支持的 RGBA16F 格式不再回退 DLSS。
- **超分**：仅 RTX 20 / 30，可选 Off、M-INT8、L-INT8、M-FP16、L-FP16，明确指定预设与内核，影响所有画质档。质量、平衡和 DLAA 下可能比游戏原生预设 K 更慢。旧版 On 没有一一对应的新模式，管理器保留旧值并要求在应用 0.4.1 前主动选择，不擅自更改画质。
- **部署与恢复**：沿用一个代理和完整 `dlssg_sm86/` 运行目录，升级时只清理能确认归属的多余代理，保留原部署记录与备份。下载不修改游戏，应用后再重启游戏。
- **日志**：普通运行日志为 `dlssg_sm86/logs/dlssg_sm86.log`，“查看日志”优先打开它；逐帧 GPU 计时另写 `frame_timing.txt`。

### 更新和批量操作

1. **更新本地负载**：点击「下载 / 更新 Mod 文件」，选择完整包或基础包。窗口会测速；自动模式优先使用最快的源，也可手动指定。下载支持暂停、继续和跳过当前源；已有上游 ZIP 可直接拖入窗口导入。**下载或导入只更新本地负载，不自动修改游戏。**
2. **勾选目标游戏**：点击「勾选可更新」，或手动勾选需要处理的游戏。
3. **执行批量操作**：确认列表中的搜索和状态筛选，点击「部署所选」（批量恢复同样需要先勾选）。常规批量操作**只处理当前可见且勾选的游戏**，隐藏勾选数量会单独提示。
4. **查看结果与重试**：查看逐项结果；「重试失败项」仅处理上次失败的游戏，不受当前可见范围限制。

- **自动接管手工安装**：检查状态时，程序会自动接管已识别的手工安装，包括按固定哈希识别的社区版代理，无需单独操作。接管只登记现有文件，不改写游戏目录；手工安装没有原始备份，已有管理记录和备份会保留。

## 恢复、数据与故障处理

### 恢复与保护机制

- **文件归属校验**：只有能证明是本项目写入的文件才会被覆盖或删除——依据部署记录中的哈希、发布版清单中的哈希，或固定指纹的项目签名；配置文件结合记录和项目特征识别。无法确认归属的文件一律保留。被替换的原文件会先备份，恢复时核对哈希后按记录还原。
- **运行目录清理**：运行目录中的组件逐文件记录哈希；恢复保留未知文件及无法确认归属的替换文件，只有勾选删除日志才清理 `dlssg_sm86/logs/`。
- **中断保护**：部署和恢复的每一步都先写入操作日志。断电或强制结束后，下次启动会自动撤销未完成的部署、补完未完成的恢复。
- **游戏库保护**：每次保存都保留上一份 `library.json.bak`；游戏库损坏时会另存原文件并载入备份，不会用空库覆盖。
- **退出保护**：操作进行中关闭窗口，会提示等待收尾；下载可以取消后退出。请保留游戏库和恢复备份，方便后续恢复已管理的安装。

### 数据位置

| 数据 | 位置 |
|---|---|
| 游戏库、管理器日志与恢复备份 | `%APPDATA%\DLSSGManager\` |
| Mod 文件 | 优先使用程序旁的 `mod/`；下载目标不可写时使用 `%APPDATA%\DLSSGManager\mod`。每个版本存放在 `versions\<版本>\`，保留上一版 |
| 游戏内 Mod 日志 | 游戏渲染目录下的 `dlssg_sm86\logs` |

### 常见处理方式

- **下载失败**：换一个下载源重试，查看运行日志中的具体原因。
- **找不到游戏 / 目录不对**：手动添加游戏，检查渲染目录；支持的游戏结构可用「定位渲染目录」。
- **无法部署 / 文件被占用**：先关闭游戏；若是目录权限问题，部署或恢复时会询问是否只为这一次操作提权（确认后出现系统的管理员授权提示）。
- **部署后无效果或崩溃**：检查游戏前置、代理入口、游戏内帧生成设置及 Mod 日志。可先恢复，按上游说明重新排查。
- **想切回原版**：关闭游戏后执行恢复。恢复时可选择同时删除 Mod 日志。
